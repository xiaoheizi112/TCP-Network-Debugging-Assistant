# TCP网络调试助手

## 1. 项目介绍

一个基于Qt框架开发的跨平台TCP网络通信调试工具，提供客户端和服务端双向通信测试功能。

## 2. 项目背景

在网络应用开发过程中，开发者经常需要验证TCP连接的稳定性、测试数据传输的正确性以及调试网络通信问题。传统的网络调试方法往往需要编写复杂的测试代码或使用命令行工具，操作繁琐且不够直观。本项目应运而生，旨在为开发者和网络工程师提供一个简单易用的图形化TCP网络调试解决方案，让网络通信测试变得高效便捷。

## 3. 技术栈

### 开发框架（开发环境）
- **Qt 5.15.2**: 跨平台C++图形用户界面应用程序开发框架
- **C++17**: 范围基于的for循环、auto关键字类推导、Lambda表达式、override关键字等等
- **qmake**: Qt官方构建系统，支持跨平台编译
- **Qt Creator**: 集成开发环境（推荐）

### 核心版块（项目重要组成部分）
- **TCP服务端模块**: 基于QTcpServer实现多客户端连接管理
- **TCP客户端模块**: 基于QTcpSocket实现服务器连接和数据通信
- **用户界面模块**: 基于Qt Widgets的图形化操作界面
- **自定义组件模块**: 增强型下拉框组件，支持动态刷新功能

### 技术支持（相关技术栈）
- **Qt Network模块**: 提供TCP/IP网络编程支持
- **Qt信号槽机制**: 实现异步事件处理和组件间通信
- **QTimer定时器**: 实现连接超时检测机制
- **Qt资源系统**: 管理应用程序图标和资源文件
- **Qt Designer**: 可视化界面设计工具

## 4. 项目功能

### TCP服务端功能
- **多IP地址支持**: 自动检测并列出所有可用的IPv4网络接口，支持选择特定IP进行监听
- **端口监听管理**: 支持自定义端口号，提供开始/停止监听功能
- **多客户端连接**: 同时处理多个客户端连接，实时显示连接数量和状态
- **客户端选择通信**: 通过下拉框选择特定客户端进行点对点消息发送
- **实时数据收发**: 接收所有客户端数据并支持向指定客户端发送消息
- **连接状态监控**: 实时监控客户端连接、断开等状态变化
- **通信日志记录**: 详细记录所有网络通信活动，便于调试分析

### TCP客户端功能
- **服务器连接**: 支持自定义IP地址和端口连接到目标服务器
- **连接超时检测**: 内置5秒连接超时机制，避免长时间等待
- **双向数据传输**: 支持文本数据的发送和接收功能
- **连接状态管理**: 实时显示连接状态，支持主动断开连接
- **消息区分显示**: 发送消息显示为红色，接收消息显示为黑色，便于区分
- **自动滚动显示**: 消息窗口自动滚动到最新内容，保持最佳用户体验

## 6. 使用说明

### 服务端操作流程
1. **启动服务端程序**: 运行TcpServer可执行文件
2. **选择监听IP**: 从IP地址下拉框中选择要监听的网络接口
3. **设置端口号**: 在端口输入框中输入监听端口（默认8888）
4. **开始监听**: 点击"开始监听"按钮启动TCP服务器
5. **等待客户端连接**: 服务器开始监听，等待客户端连接
6. **选择目标客户端**: 从客户端列表中选择要通信的客户端
7. **发送消息**: 在消息输入框中输入内容，点击"发送"按钮
8. **查看通信记录**: 在消息显示区域查看所有通信历史
9. **停止服务**: 点击"停止监听"按钮关闭服务器

### 客户端操作流程
1. **启动客户端程序**: 运行TcpClient可执行文件
2. **输入服务器信息**: 填写服务器IP地址和端口号
3. **建立连接**: 点击"连接"按钮连接到服务器
4. **确认连接状态**: 查看连接状态提示，确保连接成功
5. **发送消息**: 在消息输入框中输入内容，点击"发送"按钮
6. **接收消息**: 在消息显示区域查看服务器发送的消息
7. **断开连接**: 点击"断开连接"按钮主动断开与服务器的连接

## 7. 编写项目时遇到的问题及解决方法

### 问题一：为什么每次客户端断开后重新连接时，连接成功的信息词会随着重新连接的次数增多累加显示在客户端接收框当中？
**答**:信号与槽的“重复绑定”造成的，因为每当我新连接时，以前旧的信号槽跟着一起绑定上了，第一次连接时绑定 1 次，断开后第二次连接又绑定 1 次，此时socket的connected()信号会触发 2 次提示；第三次连接绑定 3 次，触发 3 次提示，以此类推。所以每次新绑定前接触就绑定即可，使用disconnect解除之前空的信号槽。

### 问题二：为什么服务端的ConnectedState和ConnectingState状态没有显示预期效果？
**答**:一方面服务端的ConnectedState和ConnectingState状态是在服务端程序中实现的。服务端程序中只有在客户端成功连接上后，才会触发connected()信号，才会改变ConnectedState状态为true。所以服务端的ConnectedState和ConnectingState状态只有在客户端成功连接上后才会改变。另一方面ConnectedState和ConnectingState共用同一个处理分支，ConnectingState是一个过渡状态，从调用connectToHost()到连接成功的时间非常短，可能在你看到界面输出前就已经切换到ConnectedState或UnconnectedState了，所以很难捕捉到这个状态的输出。
